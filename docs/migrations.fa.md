# راهنمای مهاجرت‌های دیتابیس MirrorHub

این پوشه شامل تغییرات نسخه‌بندی‌شدهٔ ساختار دیتابیس است. مهاجرت‌ها را به ترتیب شماره اجرا کنید و فایل‌های قبلی را دوباره اجرا نکنید، مگر آن‌که خود فایل صراحتاً اجرای تکراری را پشتیبانی کند.

## قواعد ضروری

1. پیش از هر مهاجرت، از کل دیتابیس نسخهٔ پشتیبان قابل‌بازیابی تهیه کنید.
2. مهاجرت را ابتدا روی یک کپی آزمایشی از دیتابیس اجرا کنید.
3. فایل SQL را با همان موتور دیتابیسی اجرا کنید که MirrorHub روی آن نصب است (MySQL یا MariaDB سازگار).
4. خروجی و خطاهای اجرای SQL را بررسی کنید؛ صرفاً بازشدن صفحهٔ سایت به معنی موفقیت مهاجرت نیست.
5. تا وقتی نسخهٔ برنامه با ساختار جدید سازگار نشده، نسخهٔ قبلی دیتابیس را حذف یا ستون‌های قدیمی را تغییر ندهید.
6. مهاجرت‌ها را در زمان کم‌ترافیک اجرا کنید. دستورات DDL در MySQL ممکن است commit ضمنی داشته باشند و الزاماً با ROLLBACK برنمی‌گردند.

## مهاجرت 003 — Endpointهای مستقل میرورها

فایل: `003_mirror_endpoints.sql`

این مهاجرت جدول `mirror_endpoints` را ایجاد می‌کند تا هر میرور بتواند چند آدرس مستقل داشته باشد. برای سازگاری با نسخهٔ فعلی:

- ستون `mirrors.url` حذف یا تغییر نمی‌کند.
- آدرس فعلی هر میرور به‌عنوان یک Endpoint اصلی با برچسب «آدرس اصلی» منتقل می‌شود.
- فعال‌بودن Endpoint اولیه از وضعیت فعلی میرور کپی می‌شود.
- رابطهٔ Endpoint با میرور با کلید خارجی و حذف آبشاری حفظ می‌شود.
- اجرای دوبارهٔ بخش انتقال داده، برای همان میرور و URL رکورد تکراری ایجاد نمی‌کند.
- نسخهٔ ۴ بکاپ، Endpointها را نیز ذخیره و بازیابی می‌کند؛ بکاپ‌های نسخهٔ ۱ تا ۳ در حالت ادغام پشتیبانی می‌شوند و برای میرورهای قدیمی Endpoint اصلی از URL قبلی ساخته می‌شود. بازیابی جایگزین با بکاپ قدیمی همچنان برای جلوگیری از حذف داده‌های جدیدتر مسدود می‌ماند.

### اجرای آزمایشی و عملیاتی

ابتدا از دیتابیس نسخهٔ پشتیبان بگیرید. سپس در phpMyAdmin دیتابیس موردنظر را انتخاب کنید، فایل SQL را در زبانهٔ Import وارد کنید و اجرا کنید. در محیط خط فرمان نیز می‌توانید از این الگو استفاده کنید:

```sh
mysql --host=DB_HOST --user=DB_USER --password DB_NAME < migrations/003_mirror_endpoints.sql
```

مقادیر نمونهٔ بالا را با تنظیمات واقعی سرور جایگزین کنید. رمز عبور را داخل دستور یا تاریخچهٔ shell قرار ندهید.

پس از اجرا، این دو بررسی را انجام دهید:

```sql
SELECT COUNT(*) AS mirrors_count FROM mirrors;
SELECT COUNT(*) AS endpoints_count FROM mirror_endpoints;
```

برای هر میرور دارای URL باید حداقل یک Endpoint اولیه وجود داشته باشد:

```sql
SELECT m.id, m.name_fa, m.url
FROM mirrors AS m
LEFT JOIN mirror_endpoints AS e
  ON e.mirror_id = m.id AND e.url = m.url
WHERE m.url <> '' AND e.id IS NULL;
```

کوئری آخر باید هیچ ردیفی برنگرداند. پس از اجرای مهاجرت، فرم مدیریت میرورها امکان ثبت آدرس اصلی و آدرس‌های جایگزین را فراهم می‌کند. تا پیش از اجرای مهاجرت، پنل همچنان با فیلد آدرس اصلی به شکل قدیمی کار می‌کند و امکان ذخیره چند آدرس فعال نخواهد بود. در این مرحله صفحات عمومی و پایشگر هنوز از ستون قدیمی `mirrors.url` استفاده می‌کنند؛ اتصال آن‌ها به Endpointها در مراحل بعدی انجام می‌شود.
